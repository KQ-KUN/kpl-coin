# KPL Coin / KPL 硬币模拟器

给你10,000枚硬币，重新走一遍KPL历史。独立静态网页。0.5.0 死忠模式默认选择“全部比赛”，2,631 场；可筛选“联赛”1,989 场或“杯赛”642 场，三者使用同一扩展模型，不重新计算赔率。历史操盘隐藏赛事类型，使用完整资料中的赛季和战队挑战范围，不继承死忠模式筛选；返回死忠模式恢复原筛选。联赛包含年度总决赛，杯赛包含已验收的选拔赛。原 V1 冻结版保留用于审计，不再作为首页选项。赔率均为模型模拟赔率，并非历史真实盘口。仅虚拟计分，真实历史系列赛果；没有充值、提现、购买、兑换或账户绑定。

当前扩展模型 `elo-day-official-v2.1.0` 复用原 Elo 函数与全部参数，新增历史输入会改变后续评级及模拟倍率，因此单独标版本。原 `elo-day-v1.0.0` 和0.4扩展 `elo-day-official-v2.0.0` 的数据及模型输出完整保留。没有校准或收益目标调参。2022世冠补充审计见 [报告](../kic2022-audit/reports/AUDIT.md)；0.4原报告保留在 [原扩展报告](../expansion/reports/AUDIT.md)。

奖杯口径为 KPL 官方顶级赛事体系，截至 2026 夏季赛，40 届冠军档案，狼队 11 冠、AG 8 冠、eStar 8 冠。包括联赛、年度总决赛、冠军杯、世冠、冬冠、挑战者杯；赛事选拔赛不额外算一座奖杯。2022世冠已取得腾讯TGA官方130场逐场赛程：82场选拔/淘汰比赛进入预测，48场BO2在结算后展示只读档案，其中3场平局，整段均不参与Elo及账本。2023 世冠整个 BO2 阶段仍仅作审计档案；2020 年前仅展示荣誉。部分早期奖杯是历史档案、媒体及二手资料佐证，不宣称 40 项全部具有独立官方一手资料。新增杯赛采用单一官方源字段验收，部分其它杯赛阶段/历史队名以及真实时刻仍存在待核验项。

荣誉仅是历史事实展示，不是玩家的奖杯奖励，不影响余额或参与统计。新出现且身份未经连续性核验的队伍按赛事隔离，不能把112个评级实体说成112家互不相同的俱乐部。本命选择仅显示27个原验收KPL/K甲实体，桌面三行，手机保留三行高的滚动区；杯赛筛选仅列该范围有比赛的本命。全部112个实体及比赛仍保留在历史操盘资料中。队徽沿用已有26份快照，另按已有2022夏季赛快照补齐火豹历史队徽，来源见[展示资源增补](docs/UI_ASSETS.md)；其余缺图队伍使用文字占位。

当前默认“全部比赛”的死忠验收值：**AG 327场、13,572.36枚；狼队347场、14,420.84枚；eStar284场、9,860.79枚**。当前扩展“联赛”AG268场、11,627.89枚；“杯赛”AG59场、11,944.47枚。旧V1的268场、12,077.03枚仅供 `?dataset=v1` 冻结审计，不得当作默认结果。三种赛事范围使用同一扩展模型；相同联赛场数不代表与V1价格相同。

## 本地运行

需要Node.js24，验收版本24.19.0，见.node-version。零安装依赖，可直接构建，也支持`npm ci --ignore-scripts --no-audit --no-fund`。无需kpl2k仓库、Python、数据库或赔率API。Windows双击本目录的`START-KPL-COIN.cmd`，构建完成后会打开默认浏览器。窗口需保持运行，按Ctrl+C关闭。

也可在本目录执行：

```powershell
npm run build
npm start
```

然后打开 [本地网页](http://127.0.0.1:5178)。如端口占用，可在PowerShell指定`$env:COIN_PORT=5180`再运行`npm start`。请通过本地静态服务打开；直接双击`index.html`的file协议通常无法fetch数据。

模拟平台子路径用`npm start -- --coin-path`，打开http://127.0.0.1:5178/coin/。此服务只绑定localhost，不是生产上线或手机局域网服务。

## 玩法

死忠模式选择有真实历史记录的战队，自动从其范围内第一场正式系列开始，每场固定支持本命100枚。初始10,000，默认3×；保留1×/3×/10×及极速回顾。当前扩展AG全部327场，既往本地桌面极速约14秒，仅作性能参考，真机待验证。可以随时暂停、跳至结算、重启或更换战队。后进入联赛的战队显示实际首参年份，不补造2020年的比赛。

历史操盘首次默认一个赛季加一支战队（2020春AG有18场），也可选择赛季全部比赛、战队当前资料完整队史和全历史高级挑战。赛事类型隐藏，使用完整扩展资料，不继承死忠筛选。开始前显示真实数量和日期范围，零场范围禁用。默认100枚，选A/B后再点确认，立即显示这一场真实比分与收益；可改为50/200/500，也可一键跳过。“继续历史”直接进入下一场赛前卡片，不插入日期批或赛季确认页。余额不足的金额禁用，结束回放只跳过以后未选择的比赛。

当前0.5.0继续使用自0.3.2引入的 `series-reveal-v1` 操盘交互：复用唯一账本，按比赛回放顺序逐场结算，曲线使用比赛展示日期。它与冻结日期批模式的资金可用时点、逐步回撤和可参与余额可能不同，不应当作真实历史资讯与资金时序的还原。原始比赛日期、结果可用日期与近五场截止规则保留。死忠仍采用日期批引擎；两种资料各自的冻结结果不变。

赛前近五场只使用结果可用日期严格早于本场开赛日期的已验收比赛，来自完整历史，不受挑战筛选影响。数据不足时显示实际可用数量，不补造记录。

比赛卡片上方提供“后退 / 前进”。后退自动暂停，只回看已经揭晓的比赛；前进可返回当前进度，再继续回放。回看卡片显示“当时资产”，顶部仍显示当前资产，不撤销预测、不重复结算、不泄露未揭晓赛果。重新开始或更换筛选会清空回看记录。右上角状态位置固定，揭晓结果保留红涨绿跌的金额反馈，去掉侧边色线和可见的揭晓说明小字。

结算保留全部C指标，并增加单场最大净收益/亏损、最辉煌/最惨淡赛季、带队徽的手机战绩卡。可展开逐季结果、复制摘要。没有参与的比赛不算命中率，极值按已参与并结算的比赛计算。0.5.0 增加本地续玩：返回首页、隐藏或刷新前保存操作记录；恢复时通过原引擎和唯一账本重放，默认暂停。同一存档重复恢复不会多结算。存档绑定游戏版本、数据及账本哈希、模式、队伍与范围；损坏或版本不兼容时明确提示并保留原存档。首页可明确重新开始；开始新挑战会替换旧存档。

## 项目结构

```text
frontend/
  index.html / styles.css      刊物式页面与响应布局
  src/data.mjs                正式schema解码、校验、数据加载
  src/engine.mjs              日期批回放、两种玩法、单计时器控制
  src/interactive.mjs         独立的逐场操盘交互，复用冻结引擎/账本/统计
  src/competition.mjs         全部比赛、联赛、杯赛过滤，保留完整过去战绩索引
  src/review.mjs              已揭晓比赛的只读回看，不调用账本
  src/presentation.mjs        本命展示范围、按精确实体绑定历史队徽
  src/app.mjs                 页面状态与操作、复用SVG曲线
  src/checkpoint.mjs          版本绑定的操作记录与原引擎重放
  src/challenge.mjs           四种挑战过滤、严格过去的近五场索引
  runtime/ledger.mjs          B唯一JS账本的原字节依赖快照
  data/coin-ui-v1.json        轻量正式UI数据，1,989场
  data/coin-official-v2.1.json 当前默认扩展数据，2,631场及2022 BO2档案
  data/assets-manifest.json   数据、账本和队徽哈希
  assets/teams/               26份已有队徽快照及独立火豹历史补图
  scripts/build.mjs           零新增依赖的独立静态构建
  scripts/serve.mjs           仅127.0.0.1本地静态服务
  tools/export_ui_data.py     从A/B生成冻结资产，日常构建不运行它
  tests/fixtures/             B完整样本和A必要验收字段，不进入dist
  tests/                     逻辑测试与浏览器交互验收
  verification/screenshots/  实际浏览器页面截图
  verification-d/            D测试、耗时、C/D对比及新截图
  dist/                      可分发静态构建；不作为源码修改
  docs/                      工程、schema及验收说明
```

普通构建只读取本前端冻结文件，可独立复制/解压运行。资产重生成需要原A/B验收包，和日常游玩分开；队徽已在前端冻结，完整验收包重生成也无需原kpl2k目录。金额公式只有B账本一份，C引擎只是调用`place`/`settle`，没有复制另一套倍率收益运算。

## 验收边界

V1运行时JSON为274553字节；当前扩展版416245字节（约406.49KiB），低于512KiB预算。首次加载只请求所选版本，不同时加载两份比赛数据。没有加载大型审计文件、第三方字体或在线盘口。正式schema、数据质量和金额说明见[数据与引擎合同](docs/DATA_AND_ENGINE.md)。

页面是桌面Edge的移动视口验证，尚未在真实手机、移动Safari或低性能设备实测。自动暂停用受控visibilitychange检查，复制摘要用测试替身验证文字，未访问个人剪贴板。26份队徽原样保留；新火豹图仅绑定其2022历史实体，UUG及同provider_id的杯赛待核实体均不继承。

当前本地版本为0.5.0：增加本地操作重放续玩、明确运行文件清单与最终资源manifest；待结算标签与金额分列固定，本命区收为三行，补齐火豹图，历史操盘独立于死忠赛事筛选。保留已揭晓比赛回看、2022世冠、BO2只读档案、两次点击操盘、红涨绿跌和稳定单页布局。原E验收包0.3.0、原0.4官方扩展包与0.4.1验收包均保持不变。平台当前已启用 Coin；埋点仍按产品开关关闭。本批没有修改生产注册表、推送或部署。历史发布情况应读取对应版本证据，不继承旧阶段的“未注册”判断。数据与队徽的公开再分发许可尚未确认，见[NOTICE](NOTICE.md)。发布规则见[发布合同](docs/RELEASE_CONTRACT.md)，手机人工测试见[自测清单](docs/MOBILE_SELF_TEST.md)。新的发布动作需要另行授权。最短维护命令和本批边界见 [维护说明](docs/MAINTENANCE.md)。
