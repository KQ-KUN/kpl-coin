# KPL GAME UI 规范 v2 · Editorial / Sports Magazine

确认日期：2026-09-28。用户已选择方案 B「体育刊物式目录」，本规范替代 v1 的视觉基线，作为当前 KPL GAME 项目后续网页制作、新游戏接入和页面改版的默认 UI 标准。

适用：首页、更新公告、子游戏入口、图鉴、赛程、游戏交互页和后续新页面。旧页面按后续任务逐步迁移，本次规范更新不表示网页已经实现或通过视觉验收；不涉及本项目之外的网站，也不自动覆盖其他独立仓库的规则文件。

首页细节见 [EDITORIAL_IMPLEMENTATION](EDITORIAL_IMPLEMENTATION.md)。视觉参考见 [用户选定的 B 方案](design/editorial-reference.png)。参考图确认排版气质，真实文案、字体、图标、尺寸、行为和可访问性以本规范为准。

## 1. 设计原则

- 暖纸色背景、深色正文、宋体/衬线展示标题、横向栏目、细分隔线、小圆角、无投影。
- 品牌名称和实际产品内容延续现有配置，保持非官方粉丝自制项目身份。
- 刊物气质集中在刊头、标题、栏目名称和序号；正文、导航、按钮、表单、比分和选手数据使用无衬线字体。
- 首页入口等权重，不编造排名、在线人数、赛事数据或英文标语。序号只表示注册表启用项的展示顺序。
- 2026-09-28 首页补充确认：刊头为放大的 `KPL GAME`，副标题为「KPL非官方游戏站」；每个游戏入口使用独立完整方框，后续入口设计也不能只用相邻横线区分。底部辅助入口采用轻微倾斜的平行四边形，文字保持直立；游戏图标使用直观的手工 SVG。
- 游戏保留适合玩法的布局，不把首页横向目录机械套入 BP、阵容、猜谜、关系链或表格。
- 禁止环境渐变、纸张噪点、玻璃拟态、霓虹、粒子、HUD、循环发光、卡片浮起和大面积装饰图；保留真实品牌/玩法所必需的图像与数据颜色。

| 状态 | 前景 / 背景 | 必须同时呈现 |
| --- | --- | --- |
| Success | `#24623B` / `#EAF3E9` | 正确、完成等文字或符号 |

本次已计算的对比度：正文/背景 14.07:1，辅助文字/背景 5.40:1，白字/红按钮 6.96:1，白字/蓝按钮 9.35:1，白字/紫按钮 8.03:1，控件边框/Surface 4.12:1。四种状态文字/底色均超过 4.5:1。装饰分隔线不能作为控件唯一可见边界。

## 3. Typography

| 角色 | 字体栈 |
| --- | --- |
| 中文展示标题 | `"Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", SimSun, serif` |
| 英文品牌/游戏展示名称 | `Georgia, "Times New Roman", serif` |
| 正文、导航、按钮、表单、数据 | `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` |

字体栈仅使用设备已安装字体，不代表新增字体文件。中英文展示字族在品牌/标题的语言片段上分别设置，英文部分可标记 `lang="en"`；不把整页强制套入英文衬线字体。首轮不下载字体，不请求 Google Fonts 或其他运行时字体 CDN。若未来需要一致的中文字形，另行确认授权、许可、同源打包和体积。

| --- | --- | --- | --- | --- |
| 品牌刊头 | 28px | 36px | 44px | 700 / 1.1 |
| Portal 主刊头 | 40px | 56px | 72px | 700 / 1.2；仅首页 KPL GAME |
| 首页 Hero | 36px | 46px | 60px | 700 / 1.2 |
| 内页 H1 | 32px | 38px | 44px | 700 / 1.25 |
| 区块 H2 | 24px | 28px | 32px | 700 / 1.3 |
| 游戏栏目标题 | 24px | 26px | 28px | 700 / 1.25 |
| 目录序号 | 32px | 40px | 48px | 400 / 1 |
| 正文 | 16px | 16px | 16px | 400 / 1.7 |
| 表单/按钮 | 16px | 16px | 16px | 400 / 1.5；按钮 600 |
| 紧凑数据/辅助文字 | 14px | 14px | 14px | 400 / 1.6 |

- 中文字距正常；英文品牌可用 `-.02em`，游戏名称不加宽字距；短分类标签可用 `.04em`。
- 标题自然换行；不以缩到 12px 以下、强制单行或隐藏关键文字解决拥挤。重要信息不使用 10/11px。
- 正文阅读宽度 640–760px；数据表用 14–16px 无衬线，数字可启用 `tabular-nums`。
- 不使用 900/950 等极重字重制造宋体标题；系统字体缺少真正粗体时接受设备差异，不强求像素级复刻参考图。

## 4. Layout / Spacing / Radius

| 项目 | 规范 |
| --- | --- |
| 主内容最大宽度 | 1200px；1440px 视口左右各 120px |
| 阅读内容宽度 | 640–760px；公告页主容器最多 960px |
| 页面左右留白 | <768px 为 16px；768–1023px 为 24px；≥1024px 为至少 32px，按最大宽度居中 |
| Spacing scale | 4 / 8 / 16 / 24 / 32 / 48 / 64 / 96px |
| 内容区间距 | 手机 32px；平板 48px；桌面 64px |
| 栏目内间距 | 手机 16px；平板 24px；桌面 32px |
| Radius | 目录栏目 0；按钮/输入框 4px；资料分区/图标容器 8px；Dialog 8px |
| Border | 栏目/分区 1px；刊头主线 2px |
| Shadow | 默认与 Hover 均为 `none`；Dialog 依靠遮罩建立层级 |

内容随文档流动，不使用全屏垂直居中、固定页面高度或滚动吸附。公告日期和其他真实数值不得因装饰需要改写。

## 5. Component Contract

| 组件 | 外观与布局 | 行为与状态 |
| --- | --- | --- |
| Header / Nav | 品牌衬线刊头、文字导航、底部 2px 主线；默认不悬浮 | 真实链接；当前页用字重+下划线并标记 `aria-current="page"`；同页锚点不误标当前页 |
| 首页游戏栏目 | 序号、图标、名称/分类、进入入口；每项独立完整方框、Control border、小间隔、无大圆角 | 整行一个链接；「进入游戏」是内部的按钮外观文本，不嵌套交互元素；Enter 可进入 |
| 首页辅助入口 | 轻微倾斜的平行四边形，文字直立，无投影；桌面四列、手机 2×2 | 点击与 Focus 区域清楚，不因倾斜溢出或裁切文字；其余控件维持 4px 圆角基线 |
| Button | 4px 圆角，至少 44px 高，左右内边距 20–24px；游戏按钮用对应 accent | 导航用链接，页面操作用 button；白字实底或清楚的次级描边；Disabled 保留边界和禁用说明 |
| Footer Link | 无衬线 14px、辅助色文字、Hover 下划线 | 链接区至少 44px 高、相邻间距 ≥8px；仅使用已核对的真实目标 |
| Input / Select | Surface 底、1px Control border、4px 圆角、16px 字号、至少 44px 高 | 必须有 label；错误紧邻字段且关联说明；不能只有 placeholder |
| Tabs / Filter | 文本式标签或 4px 短按钮；底部线或明确选择底色 | 选中同时有标记；区分链接导航与面板切换语义；手机允许换行或独立滚动 |
| 资料分区 / Table | 标题和分隔线组织；无投影；表头无衬线 | 保留排序/操作提示；表格独立横向滚动或转移动卡片，页面本身不横向溢出 |
| 状态 / Empty | 平面语义底色、文字与符号；空状态说明下一步 | 未知不渲染为 0；加载/错误不冒充真实记录；状态变化适当使用 `aria-live` |
| Dialog | Surface 底、8px 圆角，遮罩 `rgba(35,35,35,.45)` | 有名称、可见关闭按钮、焦点约束、关闭后恢复；窄屏可滚动；保留已有未保存数据确认行为 |

### 通用状态

- Hover：栏目用 Hover 底色，文字链接加下划线，实色按钮用对应 Hover 色；不改边框宽度、不浮起、不放大。
- Active：栏目/按钮使用对应 Active 色，不改变布局，不缩放。
- Focus-visible：3px Focus 实线、offset 3px，不被父级裁切；未来深色主题需换足够亮的轮廓并重新验证。
- Selected：下划线、勾选或明确标记与颜色同时出现，不造成位置跳动。
- Disabled：Active 表面、Muted 文字、Control border，不用整体透明度抹掉文字；原生禁用控件不响应点击。

## 6. Motion

强度很低。仅背景色、文字色、按钮色使用 150ms `ease-out` 过渡；箭头反馈最多水平移动 2px、150ms，且只在支持 Hover 的精确指针上启用。

无页面进入动画、滚动揭示、序号跳动和循环背景。`prefers-reduced-motion: reduce` 关闭非必要 animation、transition 和平滑滚动，选择状态仍须可见。

玩法必需的播放和反馈不被装饰规范误删；按具体任务设计，可暂停/跳过，并保留 reduced-motion 降级。

## 7. Responsive

| 视口 | 首页 | 游戏/资料页 |
| --- | --- | --- |
| 320 / 375 / 390px | 居中刊头与短副标题；独立方框入口纵向排列，行内「序号+图标+名称/分类+箭头」；辅助区 2×2 | 单列主操作；长名称换行；触摸不依赖 Hover；Modal 可滚动 |
| 768px | 居中刊头；方框入口横排，名称/分类可换行；辅助区四列 | 依玩法一至两列；表格独立滚动；不缩小重要文字换取空间 |
| 1024px | 居中刊头、横向方框栏目；内容减去左右留白；辅助区四列 | 两列或原玩法布局，检查断点衔接 |
| 1366 / 1440px | 内容上限 1200px；三个方框栏目纵向排列；辅助区四列、Footer 左对齐 | 统一字体/表面/控件；可有适合玩法的工作区宽度 |

768px 容器可用宽度约 720px：序号 40px、图标 48px、入口 128px、16px gap，文字占弹性列。1440px 下序号 48px、图标 48px、入口 144px、24px gap。文字列须允许收缩和换行。

200% 缩放、长中文队名、英文 ID 与键盘焦点不能被裁切。Header 容纳不下就换行，不为两个链接新增汉堡菜单。长名称若省略须提供可访问的完整名称；图片有合适 alt，装饰标记 `aria-hidden`。

## 8. 游戏页与深色主题

子游戏共用纸色表面、正文/控件字体、小圆角、分隔线和状态规则；入口/规则页可用衬线展示标题。游戏中比分、BP、猜谜线索和关系节点保持高可读的无衬线信息布局。

默认浅色，不新增全站主题切换。保留已有深浅切换和用户保存的选择；此次规范不授权删除现有深色主题。未来任务包含深色模式时，保留同样结构/字族，另定合格的深色 Token，不能直接把浅色值反转后宣称合规。

每个游戏提供「← 游戏中心」回到 `/`；独立本地开发允许回正式 Hub。禁止游戏间硬编码导航；图鉴/赛程是游戏内实际功能，不能为了 Footer 猜测路由。

## 9. 资源与实现边界

- 使用现有 HTML/CSS/脚本及项目依赖，不引入新 UI 框架、字体包、图标包或动效库。
- 游戏数量、顺序、名称、分类、描述、链接、图标来自 `config/games.json` 的启用项；品牌文案来自 `config/site.json`。
- 参考 PNG 仅用于审阅，不能作页面背景，不能裁切其中的文字/Logo/按钮代替真实界面。实现复用同源 SVG；去除 SVG 内底板等图标调整须单独明确范围。
- Portal 只加载自身静态资源，不预取游戏数据。图片预留尺寸、合理压缩，非首屏 lazy；未来 Timeline 按需分片；核心 HTML/CSS/JS/JSON/font/icon 同源。
- 外链资料不等于运行依赖。保留统计与隐私说明；统计失败不阻断游戏；不改变无统计 Cookie、无输入收集和无第三方运行依赖边界。
- 页面制作在各自真实业务仓库中进行，不改 `sources/` 或 `dist/` 作为源码，不把独立游戏源码迁入平台仓库。
