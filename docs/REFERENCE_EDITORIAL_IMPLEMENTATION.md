## 1. 首页结构

```text

        KPL非官方游戏站
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌──────────────────────────────────────────────────────┐
│ 01  [奖杯]     2K / 战队经营          [进入游戏 →]     │
└──────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────┐
│ 02  [人物问号] Guessing / 人物竞猜    [进入游戏 →]     │
└──────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────┐
│ 03  [链环]     Link / 关系解谜        [进入游戏 →]     │

 / 广告位招租 /  / B站账号 /  / 更新公告 /  / Bug反馈 /
────────────────────────────────────────────────────────

```

上述三项对应当前启用项；真实生成时过滤 `enabled`、按注册表顺序编号，不把 01/02/03 写死。序号为装饰，避免屏幕阅读器重复朗读。

### Header / Hero

- 仅保留居中大标题 `KPL GAME` 和副标题「KPL非官方游戏站」，分别来自 `config/site.json` 的 name / title。
- 标题手机 40px、平板 56px、桌面 72px；副标题 16px。自然换行，不缩小重要文案。
- 默认处于文档流，不 sticky；下方 2px 主线，到游戏入口间隔 24px，不以铺满固定屏幕高度为目标。

### GameRow

- 由 `config/games.json` 生成；在现有 `scripts/collect-games.mjs` 调整栏目 markup，不能仅把模板改成静态三条。
- ≥1024px：`序号 48px | 图标 48px | 文字弹性列 | 进入 144px`，gap 24px，上下 padding 16px；最小高度 88px，长内容时增长。
- 768–1023px：`序号 40px | 图标 48px | 文字弹性列 | 进入 128px`，gap 16px；名称/分类可换行，栏目高度不固定。
- <768px：`序号 24px | 图标 40px | 名称/分类 | 44px 箭头入口`，gap 8px；整行可点击。
- 每个入口使用独立 1px Control border 方框，背景为 Surface，栏目间隔 8px。后续入口也采用完整方框，不能仅以相邻横线分隔。
- 整行一个链接、一个键盘停靠点；内部按钮样式只是视觉 CTA，不能嵌套 button、链接、菜单或表单。
- 三种 CTA 用红/蓝/紫游戏 Token、白字；图标为手工 SVG：2K 奖杯、Guessing 人物与问号、Link 链环，不使用 AI 位图或字体绘字。
- Hover 改背景和链接强调，不改行高、不浮起、不投影；Focus 整行轮廓不裁切。

### Auxiliary / Footer

- 目录之后 32px 设置四个辅助入口，配置单独放在 `config/portal.json`，不混入游戏注册表。
- 桌面四列、手机 2×2；外形为 `skewX(-8deg)` 平行四边形，文字反向补偿保持直立，布局预留倾斜和焦点轮廓空间。
- 广告合作直接访问 `/cooperation.html`，联系方式从辅助入口配置生成；此页无需 JavaScript，不使用模态遮罩或广告命名的元素 id。未配置的其他地址可展开页内说明；更新公告访问现有 `/announcement.html`。配置真实 HTTPS 地址后使用新标签页。
- Footer 与辅助区相隔 24px，保留项目身份及统计说明。
- 保留线上完整非官方项目及统计说明，不直接用参考图缩写替换正式文案。
- 不创建虚假社交地址或空白链接，不编造更新日期。

## 2. 公告页

- 复用刊头与返回游戏中心；H1 用展示宋体，日期与正文用无衬线。
- 主容器上限 960px，正文阅读区上限 760px；按真实日期分组，以细线和标题分隔。
- 原正文、日期、顺序和语义保留，不把历史维护事项改写成新发布内容。
- 条目用标题＋正文与留白，不画浮起卡片；列表编号与首页目录序号区分。
- 长文不固定高度，正文行高 1.7；手机日期/标题自然换行，Footer 使用同一风格。

## 3. 子游戏后续迁移

| 页面 | 同一风格的应用 | 保留的业务结构 |
| --- | --- | --- |
| KPL 2K 入口 | 纸色、衬线页标题、红色操作、栏目分隔 | 模式入口、每日挑战、现有设置与主题能力 |
| KPL Guessing 入口 | 衬线名称、蓝色按钮、无衬线说明和控件 | 玩法入口、题目/线索、结算及分享流程 |
| KPL Link 入口 | 衬线标题、紫色操作、平面资料分区 | 难度、搜索、关系节点与路径反馈 |
| 图鉴/赛程 | 衬线页面/区块标题，无衬线列表/筛选/表头 | 搜索、分类、排序、滚动区与实际数据 |
| 游戏中页面 | Token、4px 控件圆角、可读字号与状态 | BP、阵容、猜谜网格、关系链等玩法布局 |

各游戏在独立仓库实施，不改聚合生成副本。平台规则与新游戏模板均指向 UI_STANDARD；后续其他仓库开工时显式引用平台 v2，不宣称仅更新平台文档就已同步其他仓库。

## 4. 制作顺序与范围

1. 首页实现维护于 `portal/index.html`、`portal/portal.css`、`portal/portal.js` 及 GameRow 生成脚本；公告页迁移在后续指定任务中修改 `portal/styles.css`、`portal/announcement.html`，具体文件以实际需要为限。
2. 接口不变：保留入口路径和 `data-game` 统计标记，核对生成逻辑与原访问事件，不变更游戏 ref 或启用状态。
3. 浏览器验收：按 UI_STANDARD 的视口、键盘、触摸、缩放、长文本、reduced-motion 和同源资源要求检查真实页面，修复明确失败。
4. 平台集成：跑相关测试和构建验证；提交、推送、部署须在后续用户授权范围内，本方案不自动触发发布。
5. 子游戏：在之后指定的游戏任务中逐步应用，保留功能和数据语义，记录未迁移页面，不扩大成玩法重构。

首页源文件为 `portal/index.html`、`portal/portal.css`、`portal/portal.js`，生成逻辑由 `scripts/collect-games.mjs` 调用 `scripts/portal-view.mjs`；图标维护于 `public/shared/`。本地构建和浏览器验收与正式发布分别确认。
